# Fixtures

Synthetic data for smoke-testing `run_eval.py`. **Nothing here is real.**

- `FIXTURE-COMPOUND-000` does not exist.
- Every query log entry has connector `FIXTURE` and record IDs like `FIXTURE-REC-1`.
- The one quantity in the fixture is `999 fixture-units`, which is deliberately
  meaningless.
- `ground_truth/fx01_synthetic_fixture.yaml` is marked `verified: true` only so the
  smoke test exercises the recall and false-alarm code paths. It is not an answer key
  about anything.

Kept out of `evals/runs/`, which is for real recorded skill outputs, so a fixture can
never be mistaken for one.

## Running the smoke test

```bash
python evals/run_eval.py --cases evals/fixtures/cases.yaml --ground-truth evals/fixtures/ground_truth --runs-dir evals/fixtures/runs --strict-schema
```

The three runs are built to trip every check, so a passing smoke test is one that
*reports problems*. Expected output:

| Check | Expected |
|---|---|
| Recall | 83% unweighted, 89% weighted — run 2 drops one expected liability |
| Expected answered `no_evidence_found` | `[0, 1, 0]` — run 2 looks and finds nothing |
| False alarms | 1 — run 2 flags `respiratory`, which ground truth lists absent |
| Review pile | `other` in 1 run — flagged but in neither list |
| Citation validity | 80% — run 3 has three bad claims |
| Citation problems | one each of `dangling_query`, `unbacked_record`, `empty_support` |
| Consistency | 50% Jaccard |
| Confidence agreement | 0% — run 3 grades `cv_qt_proarrhythmia` `high`, runs 1–2 say `moderate` |
| Rule problems | run 3 has a guideline ref marked `verified`, which is never permitted |
| Schema | 1 error in run 3, same cause |
| Exit code | 1 with `--strict-schema`, 0 without |

If a number here changes after you edit `run_eval.py`, either the edit is wrong or
this table needs updating. Decide which before moving on.

## Regenerating

The runs were generated by a throwaway script, not kept. To change them, edit the
JSON directly — they are small — and update the table above.
